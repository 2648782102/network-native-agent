Network-native Agent Runtime · L3

让 Agent 的运行时住在网络里

这不是聊天机器人，也不是 MCP 或插件。MCP 是工具接口；这里研究的是 Agent 运行时本体：身份、记忆、死亡、复活和分叉能不能由网络中的可验证事件链承担。

一句话：进程只是临时身体；agentId、历史与生命周期不只属于某一台机器。

传统 Agent

进程在，Agent 在；进程关掉，状态容易丢；换机器要复制文件。

本项目

签名事件链定义主体；机器和进程只是短暂身体；私钥不复制，历史可验证。

关键类比

事件链像基因 / 记忆脊柱，私有 GitHub 分支像神经系统，本地 habitat 只是身体。

一页看懂生命周期

01 · 创世

身体 A 生成密钥、公钥指纹与创世事件；identity.key 只在本机。

02 · 感知

网络天气注入事件；每次 wake 产生新 bodyId，但 agentId 不变。

03 · 网络写入

签名事件写入私有分支 nna-events/<agentId>，默认分支不动。

04 · 身体死亡

身体 A 与私钥被销毁；deaths=1，原身体不能再签名。

05 · 只读恢复

身体 B 从远端重放同一身份与 digest；没有私钥，所以不是原身体复活。

06 · 血缘分叉

观察体产生新 agentId，lineage 指向原身份；两条链各自独立。

L3 真实实验已经验证了什么

  • 身份 nna_demo000000000001
  • 远端分支 nna-events/nna_demo…
  • 事件数 19
  • replay valid
  • 原身体 死亡，未复活
  • 分叉 nna_demo000000000002
翻译成人话：Agent 在私有 GitHub 网络分支上留下签名历史；身体和私钥销毁后，另一个只读身体从网络里把它“认”回来了。身份没变、历史摘要一致；但它不能冒充原主体复活，只能作为观察者后代产生新身份。

边界，避免误读

不是开放互联网

当前是 L3：自有 Private GitHub relay，不是 L4，也不是公网生命体。

不是意识

“活着”只是运行时状态机意义上的 alive，不表示主观体验。

不评测智能

traits、credits、memory 是最小生命体征模型。

外壳朴素

现在看起来像 JSON CLI；真正的研究对象在底层运行时协议。
